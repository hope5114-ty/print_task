# 打印机任务队列 数据结构与算法课程设计
家用打印机先来先打，商用打印机紧急任务插队还能断点续打——两种场景，两套数据结构，一个项目讲透队列调度。


## 项目用途
||🏠 家用打印机|🏢 企业级打印机|
|---------|---------------------|------------------------------------|
|调度策略|先来先服务（FCFS）|四级优先级抢占 + 同级 FIFO|
|数据结构|数组循环队列|双层混合：链表 + 多循环队列|
|特色能力|撤销排队任务、硬件停止清队|紧急抢占、断点续打、动态优先级、权限管控|
|适用场景|嵌入式 / MCU 裸机|打印服务器 + 商用硬件|

## 一、整体设计思路
### 1. 业务场景模拟
#### 普通家用打印机
打印机同一时刻只能处理**一个任务**，多个用户同时提交打印任务时，遵循**先来先服务（FCFS）** 原则排队等待；支持：
- 提交任务：正常入队，队列满则拒绝提交
- 取出队首：执行打印，同一时间只运行一个任务
- 查看全部排队任务
- 判断队列是否为空、统计任务总数
- 撤销 / 停止规则（核心）
    - 软件端撤销（队列内未执行任务）：支持撤销指定位置、指定用户的单个任务，删除后后续任务自动前移，其余任务正常排队执行。
    - 硬件停止键（中断当前打印）：终止正在执行的任务，直接清空整个队列，所有排队任务全部删除，打印机停止工作。
    - 已开始打印的任务：无法单独撤销，只能整体中断 + 清队。

#### 商用企业级打印机

- **双层队列架构**：上层服务器链表（动态扩容）+ 下层硬件循环队列（固定容量），模拟真实企业级打印系统。
- **多优先级调度**：4 级优先级队列，高优先级任务优先调度，同级别 FCFS。
- **紧急任务抢占**：支持最高优先级任务强抢占当前打印任务，执行完后**断点续打**。
- **动态优先级调整**：低优先级任务排队超时自动升级，彻底解决「任务饥饿」问题。
- **权限管控系统**：区分管理员与普通用户，不同身份拥有不同的任务提交与删除权限。
- **内存安全**：完整的动态内存申请与释放逻辑，无内存泄漏。

1. 基础规则：
- 同一时刻仍只处理 1 个任务（物理打印机构串行输出）。
- 调度策略：优先级调度为主，同优先级遵循 FCFS。
    - 共 4 个优先级（0 最高、3 最低）：
    0 级：管理员 / 紧急任务；
    1 级：高管 / 核心业务；
    2 级：普通员工默认任务；
    3 级：低优先级批量任务。
- 层级：双层架构
    上层（打印服务器队列）：理论无容量上限，暂存所有提交任务。
    下层（打印机本机硬件队列）：有固定容量，常见 32/64/128 个任务；本机队列满时，新任务留在上层等待

2. 基本操作
- 任务提交：附带任务名称、页数、优先级、提交者身份，结合权限校验完成入队。
- 任务下发：将服务器中排序完成的任务，分发至打印机对应优先级队列。
- 任务执行：按优先级从高到低调度任务，高优先级优先执行。
- 任务查询：支持查看全量任务、按优先级分组查看任务。
- 任务删除：上下两层队列均支持精准删除；普通用户仅可按名称删除自己提交的任务，无权删除他人任务、无法使用按位置删除；管理员拥有全部删除权限。
- 任务抢占与断点续打：仅紧急任务支持强抢占；新紧急任务到达时，自动中断当前打印任务、缓存任务断点，执行完紧急任务后，从断点恢复原任务继续打印。
- 动态优先级调整：低优先级任务长时间排队后，自动提升优先级，解决任务 “饥饿” 问题。
- 权限管控：区分管理员 / 普通员工；普通员工禁止提交最高等级紧急任务，操作权限受限；管理员拥有全部操作权限。

3. 撤销 / 停止 / 暂停规则（和家用核心差异）
- 撤销等待任务：可单独删除任意一条排队任务，不影响其余任务正常排队。
- 暂停打印：仅暂停当前正在执行的任务，完整保留所有队列任务，支持后续恢复打印。
- 终止当前打印：仅删除正在运行的单个任务，剩余排队任务保留并继续按规则调度。
- 整机清空：独立功能接口，手动触发才会清空全队；停止、暂停、终止操作不会连带清空队列。
- 分层隔离：上层服务器队列、下层打印机队列可独立清空，互不干扰。


### 2. 核心数据结构选型
项目根据两套业务场景，选用不同数据结构，结合队列**先进先出（FIFO）**的核心特性匹配打印排队逻辑：
1. 简易家用打印机：采用数组顺序循环队列
    - 固定容量，无动态内存分配，代码轻量化，适配嵌入式裸机 / MCU 场景。
    - 结构简单、逻辑直观，适合单队列、无优先级的基础业务。
2. 商用打印机（双层混合结构）
    - 上层打印服务器：单向带头链表（链式队列），无固定容量，支持动态扩容，适合承载海量排队任务。
    - 下层物理打印机：多组独立数组循环队列，为每一级优先级单独配置队列，硬件容量固定，贴合真实商用打印机硬件设计。

### 3. 功能模块划分
#### 简单家用打印机模块
1. 基础结构体定义：打印任务、循环队列结构体
2. 队列基础操作：初始化、判空、判满、任务入队、任务出队
3. 任务管理：按位置撤销任务、按名称撤销任务、遍历查看任务、一键清空队列
4. 业务逻辑：模拟打印机持续工作，串行执行所有排队任务

#### 商用企业打印机模块
1. 枚举与结构体：用户身份、任务优先级、打印任务、断点缓存、链表节点、循环队列、整机管理结构体
2. 上层服务器（链表）：初始化、判空、入队、出队、按名称 / 按位置删除、遍历展示、队列清空、全局排序、优先级动态调整
3. 下层打印机（多循环队列）：队列初始化、判空 / 判满、入队 / 出队、按名称 / 按位置撤销任务
4. 打印状态控制：暂停打印、恢复打印、终止当前任务、分优先级展示任务、整机队列清空
5. 调度核心：任务下发、紧急任务抢占检测、打印机主调度、任务中断与断点恢复
6. 权限控制：针对不同身份，限制任务提交、任务删除等操作权限

## 二、核心数据结构定义
### 1. 家用打印机结构体
```c
#define MAX_TASK 8       // 打印机最大任务容量
#define TASK_NAME_LEN 32 // 任务名称最大长度

/* 单个打印任务结构体：存储任务基础信息 */
typedef struct
{
    char taskName[TASK_NAME_LEN]; // 文档/任务名称
    int pageCount;                // 打印页数
} PrintTask;

/* 打印机循环队列结构体 */
typedef struct
{
    PrintTask taskQueue[MAX_TASK]; // 任务数组（循环队列主体）
    int front;                     // 队头指针：取出任务位置
    int rear;                      // 队尾指针：存入任务位置
    int isBusy;                    // 打印机状态 0-空闲 1-忙碌
} Printer;
```

## 三、核心算法实现
### 普通家用打印机
基于*数组顺序循环队列*实现，单级队列结构，无分层、无优先级，纯*FIFO*调度；采用固定数组存储任务，无动态内存分配，适配嵌入式裸机环境

#### 核心参数
1. 队列最大容量：MAX_TASK = 8，贴合家用打印机硬件任务上限；
2. 任务信息：单个任务存储任务名称、打印页数；
3. 状态标记：isBusy 标识打印机忙碌 / 空闲，同一时刻仅能执行一个打印任务。

#### 核心逻辑与功能
1. 初始化：重置队头、队尾指针，清空任务数组，设置打印机为空闲状态。
2. 任务入队：队列未满时，写入任务信息并移动队尾；队列已满则拒绝添加任务。
3. 任务出队：队列非空时，取出队首任务并移动队头；队列为空则提示无任务。
4. 任务撤销
    - 支持按指定位置、指定任务名称删除排队任务；
    - 删除后后续任务自动前移，保持队列顺序；
    - 打印机工作中仅可操作软件队列，正在打印的任务无法单独撤销。
5. 打印执行：打印机置为忙碌状态，循环取出队列任务依次打印；全部任务完成后恢复空闲。
6. 硬件停止逻辑：打印过程中触发停止，终止当前任务并清空整个队列，所有排队任务一并清除。
7. 辅助功能：遍历查看全部排队任务、判断队列空 / 满、统计任务数量、一键清空队列。

### 商用打印机
#### 方案一：多独立循环队列
- 为每一个优先级单独开一条循环队列 / 单链表：
    - pri0_queue：存放 0 级紧急任务
    - pri1_queue：存放 1 级业务任务
    - pri2_queue：存放 2 级普通任务
    - pri3_queue：存放 3 级低优任务

- 取任务规则
    - 按优先级从高到低依次查询：0 → 1 → 2 → 3
    - 哪个队列不为空，就从这个队列取队首任务
    - 同一条队列内部，依旧是普通循环队列 FIFO
- 优点：
    - 逻辑直观，易调试、易维护
    - 执行效率稳定
    - 贴合真实硬件设计
- 缺点：
    - 内存占用略高
    - 优先级等级扩展有限

#### 方案二：单数组 + 遍历查找
仅使用一条循环队列存储所有优先级任务；入队直接追加到队尾（FIFO），出队时全队列遍历，选出优先级最高的任务取出执行。
- 优点：
    - 结构简单
    - 无需拆分队列
- 缺点：
    - 效率低
    - 多个同优先级任务并存时，遍历取最高优先级时，容易打乱原有入队顺序，破坏 FIFO 原则，违背业务规则
    - 无法按优先级分类查看、批量管理任务；撤销、筛选任务都需要全队列遍历，逻辑复杂

#### 方案三：二叉堆实现标准优先队列
基于数组实现小顶堆，利用堆的特性完成优先级排序；优先级 0（最高）构建小顶堆，堆顶永远是当前最优任务
- 优点：
    - 算法通用性强：是标准数据结构优先队列实现方式，理论调度效率高（入队、出队时间复杂度 O(logn)）
    - 优先级扩展灵活
- 缺点：
    - 逻辑复杂度高
    - 不便于中间位置删除、按名称删除、遍历查看排队任务等业务功能

### 两层结构对比表

| 功能点         | 家用打印机（数组循环队列） | 打印服务器（单向链表） |
| -------------- | -------------------------- | ---------------------- |
| 容量限制       | 固定容量，满则拒绝入队     | 无固定容量，动态扩容   |
| 内存分配       | 静态数组，无动态内存       | 动态节点，malloc 分配  |
| 中间删除效率   | 低（元素整体前移）         | 高（仅修改指针）       |
| 判空 / 判满    | 判空 + 判满双规则          | 仅判空，无判满         |
| 任务扩容能力   | 不可扩容                   | 运行时自由扩容         |
| 适用场景       | 嵌入式硬件设备             | 软件服务层、服务器     |

## 四、核心流程设计
1. 简易家用打印机流程
    - 程序启动：初始化循环队列，设置打印机为空闲状态。
    - 功能菜单选择：
    - 添加打印任务（入队）
    - 执行打印任务（出队 + 模拟打印）
    - 查看排队任务（遍历）
    - 按位置 / 按名称撤销任务
    - 清空队列
    - 退出程序
    - 整体遵循 FIFO 规则，串行执行所有打印任务。
2. 商用企业级打印机流程
    - 程序启动：依次初始化上层打印服务器链表、下层打印机多组循环队列及所有状态标记。
    - 功能菜单选择，覆盖全业务：
    - 提交打印任务：身份 + 权限校验，合法任务存入服务器链表
    - 任务下发：将服务器排序后的任务分发至打印机对应优先级队列
    - 执行打印：支持正常打印、暂停、恢复、紧急任务强抢占、断点续打
    - 任务管理：按名称 / 按位置撤销任务、分优先级查看任务、统计任务数量
    - 拓展功能：自动调整任务优先级、终止当前打印、分层清空队列
    - 退出程序：释放链表动态内存，避免内存泄漏
    - 整体调度规则：同优先级遵循 FIFO；高优先级优先执行；支持紧急任务中断抢占 + 断点恢复；超时任务自动升级优先级，解决任务饥饿问题。
